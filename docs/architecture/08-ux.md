# 08 — UX

Expérience cohérente, pro, sobre, orientée développeur avancé. Desktop et CLI partagent les mêmes états et signalétique.

## Desktop — layout 4 panneaux

```
┌────────────────────────────────────────────────────────────────────────────┐
│  TopBar:  Locaryn ▸ project-name   [Remote ● server — qwen2.5-coder:32b]  ⚙ │
├──────────────┬───────────────────────────────────┬─────────────────────────┤
│  Left        │  Center                            │  Right                  │
│  Sessions/   │  Chat / Tasks / Light editor      │  Artifacts / Preview    │
│  Projects    │  ┌──────────────────────────────┐ │  ┌───────────────────┐  │
│              │  │  message stream (SSE)        │ │  │  iframe sandboxed │  │
│ ▸ project A  │  │  tool calls (collapsible)    │ │  │  preview live     │  │
│   • session1 │  │  approvals (inline buttons)  │ │  │  ▸ HTML ▸ MD ▸ PNG│  │
│   • session2 │  │  code blocks (Monaco mini)   │ │  │                   │  │
│ ▸ project B  │  └──────────────────────────────┘ │  └───────────────────┘  │
│              │  Composer:  [ textarea ]  [Send ▸] │  [ open in browser ]    │
│ [+ project]  │                                    │                         │
├──────────────┴───────────────────────────────────┴─────────────────────────┤
│  Bottom:  Terminal (xterm.js)  │  Logs  │  Extensions  │  Provider status  │
└────────────────────────────────────────────────────────────────────────────┘
```

### Navigation desktop

- **Left panel:** arbre projets > sessions; bouton `+ project` (sélection dossier + trust level prompt); recherche sessions.
- **Center:** chat par défaut; onglets `Chat | Editor | Tasks`; composer en bas avec sélecteur de modèle/provider inline.
- **Right:** artefacts de la session courante; switcher de kind (HTML/MD/PNG/Plotly); bouton "open in browser" (pour debug hors sandbox).
- **Bottom:** onglets `Terminal | Logs | Extensions | Provider`; terminal lié au project actif; logs temps réel; Extensions = gestionnaire; Provider = status + switch.

### États (loading / error / offline)

| État | Affichage |
| --- | --- |
| Connexion daemon en cours | TopBar: "Connecting to local daemon…" + spinner |
| Daemon indisponible | Banner rouge: "Local daemon not running — [Start daemon]" |
| Remote connecting | TopBar: "Connecting to remote server…" |
| Remote healthy | TopBar: "Remote ● <server> — <model>" (vert) |
| Remote unhealthy (auto mode) | Banner ambre: "Remote unavailable — switched to Local (Ollama). [Retry remote]" |
| Local provider starting | TopBar: "Local ◐ starting Ollama…" + progress |
| Local provider ready | TopBar: "Local ● Ollama — <model>" (bleu) |
| Aucun provider | Banner rouge: "No provider available — [Configure]" |
| Tool approval pending | Inline dans le chat: carte "tool_call: run_command `npm test` — [Approve] [Deny] [Always for this project]" |
| Generation streaming | Cursor clignotant + tokens en flux + `task.update` progress bar |
| Generation error | Carte rouge dans le chat avec retry |
| Extension permission prompt | Modal: "Plugin `my-plugin` requests: shell, files.write — [Approve] [Deny] [Customize]" |
| Offline (no network) | TopBar: "Offline — Local mode" (pas d'erreur, comportement normal) |

### Signalétique remote vs local

- **Couleur TopBar:** Remote = vert, Local = bleu, Auto (en remote) = vert, Auto (en local après fallback) = ambre.
- **Label explicite:** toujours "Remote ● <server host> — <model>" ou "Local ● <engine> — <model>". Jamais d'ambiguïté.
- **Dans les logs:** chaque action exécutée distante est préfixée `[remote]`, locale `[local]`.
- **Lieu d'exécution:** si une commande shell tourne via remote-server, le terminal affiche un badge "executed on remote server <host>" (et réciproquement).

### Permissions & consentements

- **Trust level project** (à l'ajout): `Trusted` (full file access, auto-approve reads), `Untrusted` (approve each file access), `Sandbox` (preview-only, no shell).
- **Tool approval:** inline dans le chat; scope `once | session | project | always`.
- **Extension install:** modal de permissions (voir ci-dessus); refus = feature désactivée, agent informé.
- **MCP server registration:** prompt "MCP server `<name>` wants to expose tools: [...] — [Enable] [Disable]".
- **Preview network:** si un artefait tente `fetch()`, bloqué + prompt "Allow network for this artifact? [Once] [Session] [Deny]".

### Gestion extensions/plugins/MCP dans l'UI

- **Bottom panel > Extensions tab:** liste groupée par scope (Global / User / Workspace); colonnes: name, version, kind, enabled toggle, permissions badge; actions: Install, Enable/Disable, Remove, Reload, View manifest.
- **MCP servers:** sous-section; liste avec status (running/stopped), tools découverts (expandable), boutons Start/Stop/Discover.
- **Install flow:** `Install > choose source (path/URL) > validate manifest > permission prompt > activate`. Erreurs de validation affichées clairement (apiVersion incompatible, permissions inconnues, etc.).
- **Hot-reload:** changement de fichiers dans `.locaryn/plugins/` détecté → badge "reloaded" sur l'extension.
- **Import Claude Code/Cursor:** bouton "Import bundle" → sélection dossier → conversion → résumé des éléments importés (agents, commands, skills, mcp).

### Gestion rules workspace

- **Settings > Project > Rules:** éditeur markdown pour `LOCARYN.md` + `.locaryn/rules/*.md`; affichage de l'agrégation finale (global + workspace) avec priorité; toggle par fichier.
- **Preview du system prompt:** bouton "Preview system prompt" montrant l'assemblage rules + agent profile + skills actives.

### Sélection agents spécialisés

- **Composer:** menu déroulant "Agent: default ▸" listant les agent_profiles (default, code-reviewer, architect, tinkerer...). Sélection change le system prompt et le tool subset.
- **Délégation inline:** `/delegate code-reviewer review the auth module` lance un subagent (streaming dans le chat, badge "delegated to code-reviewer").

## CLI

### Commandes

```
locaryn                                    # aide
locaryn --version

# Connexion / mode
locaryn login --server https://host:7473 --user alice
locaryn logout
locaryn status                             # provider actif, mode, daemon, projects

# Projets / sessions
locaryn projects list
locaryn projects add <path> [--trust trusted|untrusted|sandbox]
locaryn projects open <name>
locaryn sessions list
locaryn sessions new [--project <name>]
locaryn chat [--resume <session-id>] [--agent <name>] [--no-daemon]
locaryn sessions show <id>

# Provider
locaryn provider list
locaryn provider use <id|auto|local|remote>
locaryn provider health [<id>]
locaryn provider start ollama [--model qwen2.5-coder:7b]
locaryn provider stop [ollama|llama_cpp|...]

# Extensions
locaryn plugin install <path|url> [--scope user|workspace|global]
locaryn plugin list [--scope ...]
locaryn plugin enable <name>
locaryn plugin disable <name>
locaryn plugin remove <name>
locaryn plugin reload
locaryn plugin permissions <name>          # show + grant/deny interactive

locaryn mcp list
locaryn mcp add <name> --command <cmd> [--args ...] [--env ...] [--scope ...] [--transport stdio|http]
locaryn mcp remove <name>
locaryn mcp start <name>
locaryn mcp discover <name>

locaryn commands list
locaryn skills list
locaryn agents list
locaryn rules show                          # affiche rules agrégées du projet courant
locaryn rules edit                          # ouvre $EDITOR sur LOCARYN.md

# Import compat
locaryn import claude-code <path>           # importe .claude/ bundle
locaryn import cursor <path>                # importe .cursor/ 
locaryn import continue <config.yaml>
locaryn import cline <path>

# Terminal / exec
locaryn exec "<cmd>"                        # exécute via daemon, stream stdout/stderr
locaryn artifacts list [--session <id>]
locaryn artifacts show <id>

# Daemon
locaryn daemon start [--port 7474]
locaryn daemon stop
locaryn daemon logs

# Remote-server (admin)
locaryn server users list                   # via remote SDK
locaryn server audit --since 2026-07-01

# Slash commands (dans chat)
# /refactor extract-module src/auth.ts
# /delegate code-reviewer review src/auth.ts
# /skill database-migration
```

### États CLI

| État | Affichage |
| --- | --- |
| Daemon non démarré | "Local daemon not running. Start it? [Y/n]" ou auto-start |
| Remote connecting | "Connecting to https://host:7473 ..." |
| Remote OK | header: "[remote ● host — model]" |
| Fallback local | header ambre: "[local ● ollama — model] (remote unavailable)" |
| Tool approval | prompt inline: "Approve run_command `npm test`? [y/N/always-project]" |
| Streaming | tokens affichés en flux; `Ctrl+C` pour cancel |
| Error | message rouge + hint |

### Signalétique CLI

- Header en haut de chaque commande interactive: `[remote ● host:7473 — qwen2.5-coder:32b]` ou `[local ● ollama:11434 — qwen2.5-coder:7b]`.
- `locaryn status` affiche un tableau: mode, provider actif, daemon PID/port, remote health, projets, extensions enabled.
- Lieu d'exécution: `locaryn exec` précise "executed locally" ou "executed on remote server <host>".

## Flux preview (desktop)

1. Agent émet `event: artifact` (kind html, path `artifacts/foo.html`).
2. Right panel détecte l'event, charge l'artefact depuis `GET /v1/artifacts/{id}/raw`.
3. Rendu en iframe `sandbox="allow-scripts"` + CSP `default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'`.
4. Si kind `plotly_html` ou `image_png`: affiché directement.
5. Si kind `markdown`: rendu via marked + sanitize dans le panneau (pas iframe).
6. Si kind `python_text`: préformaté monospace.
7. Live reload: si l'artefact est régénéré (même id ou `preview.update` event), l'iframe recharge.
8. "Open in browser": ouvre l'artefact dans le navigateur système (hors sandbox, pour debug — confirmation requise).

## Cohérence desktop/CLI

- Mêmes états, mêmes labels, mêmes permissions, mêmes scopes.
- Une session ouverte en CLI est visible dans le desktop (et réciproquement) via le daemon partagé.
- `locaryn chat --resume <id>` reprend exactement la session du desktop.
- Les extensions installées via CLI sont visibles dans le desktop (registry partagé en DB).
